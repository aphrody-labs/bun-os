## Sync

1. Merge upstream `main` into the fork (`git -C vendor/ui-ux-pro-max-skill fetch upstream` then
   merge). For a conflicting catalog take the upstream side and run `bun run bunify:catalogs`;
   `bun run verify` in the fork must pass. Push the fork's `main`.
2. `bun run sync:upstream -- --golden` in `packages/m3-design`: rebuilds `data/` from the fork,
   writes `upstream.json` and `LICENSE`, regenerates the upstream Python golden through `uv`,
   and lists fork changes to `SKILL.md`, `references/` and the engine to port by hand.
3. `bun run build:skill`, then `bun test`; commit the submodule bump with the regenerated files.

## What Bun OS changed

- `scripts/*.ts` is a Bun-native port of the upstream Python scripts (`core.py`,
  `design_system.py`, `reasoning_contract.py`, `search.py`, `validate_data.py`) using only Bun
  built-ins, including the `--rtl` filter. `test/upstream-golden.test.ts` checks that it prints
  the same JSON as upstream's Python on 43 fixed queries over these catalogs.
- `SKILL.md` gained the Bun OS and Aphrody Labs Material 3 contract; its commands call the Bun
  scripts (also shipped as `m3-design search` / `m3-design system`).
- `data/` is generated: the fork's catalogs byte for byte (with Bun commands instead of
  npm/pnpm/yarn), the first-party stacks of `local/stacks` (`m3`, `iced-libcosmic`, `egui`), and
  `brands.csv` generated by `scripts/brands.ts` from `@aphrody/m3-tokens` (the M3 baseline seed
  and the Bun OS product seed). The fork's retired `rg-ui` stack and its brand table are dropped.
- The design-system checklist adds Bun OS accessibility and performance items. `references/bun-os.md`
  is first-party.
- `packages/m3-design/skill/ui-ux-pro-max` is the distributable copy built by `bun run build:skill`.
