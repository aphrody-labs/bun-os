# Bun fork migration: aphrody-labs/bun on upstream Bun

The aphrody-labs/bun fork added runtime modules, `Bun.*` APIs, CLI commands, packages and engine changes on top of
oven-sh/bun. Bun OS runs **unmodified upstream Bun canary `1.4.4-canary.20261028.1`** (`bun --revision`:
`1.4.4-canary.1+11c367163`). Everything the fork added either lives on here as code on that runtime, or is listed below
with the exact reason it cannot.

- The canonical registry is [`packages/bun-os-plugins`](../../packages/bun-os-plugins). The root `bunfig.toml`
  preloads it, so the fork's `bun:*` specifiers (and its hardcoded npm builtins) resolve on upstream Bun. Each module
  stays in the package that owns its capability, which exports a `./bun-plugin`.
- Fork CLI commands become `bunos <name>`. The front door (`packages/bunos-run/src/bunos.ts`) runs `bunos-<name>`
  from PATH, else from the bins of `packages/bun-os-plugins`, which route to the Bun OS owner
  (`packages/bun-os-plugins/src/commands/index.ts`).
- `bun packages/bun-os-plugins/src/cli.ts list | check | commands` prints the registry, imports every module and shows
  where each command resolves on this host.

## Method and evidence

- Fork checkout: `toolchains/bun` (untracked, read-only), HEAD `0fceb5d6fd` (2026-10-31). Upstream: oven-sh/bun `main`.
  Merge base: `017b2439a7` (2026-10-16).
- Fork-only history is `git log --no-merges 017b2439a7..HEAD`: 2377 commits. 1218 are by aphrody-dev. The other
  ~1150 are upstream pull requests cherry-picked before oven-sh merged them, and they arrive through upstream.
- Fork-only tree is `git diff --name-status 017b2439a7 HEAD`: 44544 added, 1222 modified, 34 deleted. Of the
  additions, 14064 are `packages/bun-video`, 6774 `vendor/mullvad`, 1848 `vendor/uv` and 6940 `src/quality`.
- Most user-facing additions were imported into the fork in commit `62fcdb38ec9`. "Fork" paths below are relative to
  the fork checkout.

Status values:

- **already**: was in Bun OS before this migration pass.
- **migrated**: ported in this pass.
- **partial**: ported with the listed members missing.
- **missing**: portable to upstream Bun (Rust + bun:ffi or a subprocess) but not ported yet. The row gives the owner
  and the work left.
- **not portable**: needs a change to Bun's engine (Zig/C++/Rust linked into the `bun` binary). The row gives the
  reason and the closest userspace substitute.

## Engine-only changes (not portable)

These are changes to the `bun` binary itself. Upstream Bun ships its own version of each subsystem, and they cannot
run as code on top of it:

- Parser, printer, transpiler, bundler and codegen changes (`src/js_parser`, `src/js_printer`, `src/transpiler`,
  `src/codegen`, `src/ast`, `src/css`, `src/resolver`, `src/sourcemap`), the React compiler (`src/react_compiler`),
  the type checker and semantic analysis (`src/sema`), and the lint/format extensions (`src/quality`, ~6900 files).
  Bun OS uses upstream `bun check`, `bun lint` and `bun fmt` (root `package.json`, `bun-format.json`).
