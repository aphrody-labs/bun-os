# Token fusion: M3, Tailwind v4 and shadcn/ui

How the M3 tokens reach Material Web, Tailwind and shadcn-style components. Referenced by the
`export_*` functions of `crates/aphrody-m3-tokens` (`color.rs`, `adaptive.rs`).

## Contract

CSS custom properties are the only integration layer. They cross the shadow DOM of `md-*`
elements by inheritance; Tailwind utility classes do not. Every system consumes the same
`--md-sys-*` values generated by `crates/aphrody-m3-tokens`.

```
aphrody-m3-tokens (seed -> HCT -> roles)
  export_css               :root { --md-sys-color-* }        -> Material Web (inherits directly)
  export_shadcn_aliases    --primary: var(--md-sys-color-primary); ...   -> shadcn-style React
  export_tailwind_theme    @theme inline { --color-*: var(--md-sys-color-*) } -> Tailwind v4
  export_fusion_css        the three blocks above, in that order
  adaptive::export_breakpoints_css   --md-sys-breakpoint-* and Tailwind --breakpoint-*
```

- `FUSION_ALIAS_MAP` is the single mapping from shadcn/Tailwind names to M3 roles; both alias
  sheets read it, so they cannot drift.
- Aliases are pure `var()` references: emit them after `export_css` and light/dark switching
  flows through without regenerating them.
- `aphrody design tokens` (CLI in `../aphrody-ai`) prints the sheets: `--fusion`, `--dark`,
  `--format shadcn-registry` (a shadcn `registry:theme` item generated from the same map).
- In the Bun workspace the generated sheets are `@aphrody/m3-theme/tokens.css` and
  `tailwind.css` ([`SPACEUI-M3-FUSION.md`](../../architecture/design/SPACEUI-M3-FUSION.md)). Import one palette sheet per
  app.
- Cascade order, when mixing systems: reset, M3 tokens, Tailwind utilities, component layers,
  each in its own `@layer`.
