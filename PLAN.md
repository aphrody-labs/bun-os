## Verified architecture

- This repository owns Bun OS distribution assembly, its root Bun workspace,
  package catalog, factory and release coordination. These are repository
  ownership boundaries, not claims that all declared compositions or release
  artifacts have been built or qualified.
- The runtime is unmodified upstream Bun: npm `bun@1.4.4-canary.20261028.1`, gitHead
  `11c367163a4b`, pinned in `package.json` (`packageManager`), `sources.lock.json`
  and `distribution.json`. `bun --revision` must print `1.4.4-canary.1+11c367163`.
  The `aphrody-labs/bun` fork is abandoned and its `toolchains/bun` submodule is
  removed. Code that still calls fork-only commands or APIs (`bun mcp`,
  `bun n2b`, `bun agent-plugin`, `bun wasm`, `bun:windows`, `bun:linux`,
  `bun:nginx`, `Bun.Video`) must be migrated or removed; the `bunos` CLI now
  answers the first four with an error.
- Bun OS is an Arch-inspired Linux distribution. The final goal is Bun
  integrated into the Linux kernel the way Rust was; see
  [`docs/KERNEL-ROADMAP.md`](docs/KERNEL-ROADMAP.md).
- Product source is organized under `apps/`, `crates/` and `packages/`.
  Upstream projects and independently owned code retain their source boundaries
  and licenses.
- Rose Griffon application source belongs to `aphrody-labs/rosegriffon`.
  Bun OS no longer contains its application/package copies; the integration
  state is documented in `docs/ROSEGRIFFON.md`.
- The root Cargo workspace is not yet the sole Rust workspace. For example,
  `apps/aphrody-drive` and `packages/bun-tauri` declare nested workspaces, and
  the root manifest excludes them. Do not report Cargo consolidation complete.
- The product direction is Arch Linux with pacman/libalpm. Server, COSMIC
  Desktop and Gamescope Gaming remain distinct compositions; Alpine and Ubuntu
  are compatibility targets in the checked-in product configuration. The
  distribution manifest currently labels qualification as `development`.
- Desktop session selection is separate from OS composition. Desktop defaults
  to COSMIC, whose exact closure and boot/display qualification remain pending;
  Omarchy Hyprland is explicitly blocked until its package subset and signed
  closure are selected. Neither session is represented as qualified.
- No kernel source is selected in the root profile. The `/usr` boot path and
  gaming image's bootable target are blocked until a kernel composition and
  artifact qualification exist; container gaming continues to use its host
  kernel. CachyOS kernel packages remain catalog candidates rather than a
  default installed kernel.

## Kernel roadmap (planning only; nothing below is built or qualified)

Summarized from the 2026-10-29 research report; the claims it marks UNVERIFIED
remain UNVERIFIED here.

- Phase 0 (weeks 0-4): `linux-bun` package forked from Arch's `linux` PKGBUILD and
  a boot gate under QEMU/OVMF with Limine; an upstream-shaped `bun_accel` RFC
  branch; Bun as `/init` with a boot receipt. The earlier "6.18.55 kernel boots
  into Bun as /init" and "7 selftests passed" claims are UNVERIFIED.
- Phase 1 (months 1-3): weekly rebuilds, CI (`make LLVM=1 rustavailable`,
  selftests in QEMU), Secure Boot/UKI decision, rollback tests.
- Phase 2 (months 3-9): RFC iterations, a second maintainer, an io_uring-opcode
  variant. Predictions about upstream reception are UNVERIFIED inference.
- Phase 3 (months 6-12): Bun in userspace driving sched_ext, BPF LSM and
  cgroup/PSI.
- Phase 4 (12+ months, optional research): Rust/BPF-hosted policy language or
  Wasm-in-BPF. Not JavaScriptCore in ring 0.
- Consequence of the pin: upstream Bun does not reference `bun_accel`, so the
  `/dev/bun_accel` ioctl has no consumer until one exists outside Bun's source.

## Pending source and qualification gates

- The pacman-to-APT compatibility converter now verifies detached `.db`/`.files`
  metadata before parsing and verifies package archive signatures before
  conversion, including cached and local archives. Arch signatures require
  full/ultimate trust in the Arch GnuPG home; CachyOS requires the configured
  complete primary fingerprint. The index records metadata signature evidence,
  and conversion reports include archive signers. Qualification remains
  pending: provision and review each trust home, qualify sync and conversion on
  the VPS for Arch and CachyOS, and bind selected metadata to immutable
  repository snapshots before install/release use. Missing, invalid, expired
  or unexpected signatures must continue to fail closed. Do not weaken trust
  settings or use official-Arch-only resolver results as CachyOS evidence.
- The root manifest explicitly preserves the independent `vendor/rea` version.
  The workspace inspector requires its declared name, version and Git pin;
  all other product packages retain the shared version contract. This source
  correction still requires VPS qualification before reporting Cargo inspection
  as passing.
- Declared root submodules now have Git pins, including the Recalbox revision
  read from its upstream repository. Pins still need initialization and source
  qualification; declarations alone do not make the source graph available.
- Product payload preparation, independent CLI discovery qualification and
  receipt-bound Docker staging are implemented in the root factory graph.
  Qualification requires a complete product source closure, a matching runtime
  pin, prepared package archives/sidecars (including the generated
  `@aphrody/cli-wasm` glue, module and provenance files) and a frozen installed
  dependency tree. The product sidecar contract now admits only the exact
  generated WASM paths owned by that declared package. The WASM staging receipt
  also points to its current source file. Neither path has been built or run on
  the VPS yet.
- Product discovery proves CLI command targets, and a separate CLI-WASM gate
  verifies module initialization and pure-command help. The root `mcp`,
  `agent-plugin`, `wasm` and `n2b` commands were fork-only and were removed with
  the fork; the Rust `aphrody-mcp` server is neither packaged nor qualified by
  the root CLI. The CLI-WASM artifacts are mandatory in the frozen
  payload; qualification executes WASM initialization and pure-command help.
  FFI artifacts and their release manifest are mandatory payload inputs, and
  qualification loads the library and checks each exported ABI. The former
  agent-plugin and MCP product gates were removed with the fork's commands, so
  `container/qualify-image.ts`, `container/verify-payload.ts` and
  `container/verify-product.ts` must drop them from their required-gate lists
  before a product or image qualification can pass. The remaining gates
  still need VPS execution. The primary Arch Docker image now reruns those
  gates inside its final rootfs, records an image qualification bound to the
  product/runtime receipts, and verifies it on container health. The separate
  Alpine musl and Ubuntu compatibility image recipes keep different runtime
  ABIs and are not yet product-payload images.
- The current recursive source inventory reports 326 declarations, including
  166 root declarations and 104 unavailable root sources. The earlier 92-item
  audit count is stale; no submodule removal is justified until the recursive
  inventory and current consumers are reviewed. Material Design Icons has a
  concrete packaging gap:
  its package loads assets from `vendor/` but excludes those assets from its
  published file set. Migrate and qualify the assets, license and consumers
  before considering retirement of that vendor.

## Delivery rules

- Preserve concurrent changes, protected stores, source history and notices.
- Do not infer product admission or migration from a directory or manifest
  entry alone.
- Do not claim a build, test, deployment, binary or release without current
  evidence from its owning system.
- Commit only owned paths, fetch before a normal push, verify ancestry, and
  never force-push.
